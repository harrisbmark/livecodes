Deployment

LiveCodes uses GitHub Actions to deploy to multiple targets on push to main. Each deployment workflow is gated by repository variables or secrets so only the intended targets run.

Workflows​

Workflow fileNameTriggerGuard
deploy-ghpages.ymlDeploy to GitHub Pagespush to main(none — always runs)
deploy-docker.ymlDeploy to Dockerpush to main, manualvars.VPS_ENV must be set
deploy-php.ymlDeploy to PHPpush to main, manualvars.PHP_ENV must be set
deploy-ftp.ymlDeploy to FTPpush to main, manualvars.PHP_ENV must NOT be set
deploy-ssh.ymlDeploy via SSHpush to main, manualvars.PHP_ENV must NOT be set

Guard Logic​

  • deploy-docker runs when VPS_ENV is configured in the repository variables. This prevents the workflow from failing on forks that don't use Docker.
  • deploy-php runs when PHP_ENV is configured. It combines FTP and SSH jobs for PHP shared hosting deployments.
  • deploy-ftp and deploy-ssh run when PHP_ENV is NOT configured. They deploy static builds (without PHP server-side services) to FTP or SSH hosts. This avoids deploying to the same target from both deploy-php and the standalone workflows.

Configuration​

All deploy workflows rely on GitHub Actions secrets and variables configured in the repository settings (Settings → Secrets and variables → Actions).

  • VPS_ENV and PHP_ENV are repository variables containing non-sensitive config in .env format (key=value pairs, one per line). They act as the single source for build-time environment variables and server runtime config. Sensitive values (MySQL credentials, SSH keys, API tokens) are kept in GitHub Secrets.

For details on specific secrets and variables required by each target, see:

  • Docker Setup
  • PHP Setup

Manual Triggers​

All workflows except deploy-ghpages support workflow_dispatch for manual runs from the Actions tab. You can optionally specify a branch to deploy.
